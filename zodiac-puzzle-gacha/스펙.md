# 12간지 동물별 고유 게임 설계

- 작성일: 2026-08-19
- 상태: 초안 (사용자 검토 대기)

## 0. 결정 필요 사항 (검토 후 확정해주세요)

이 문서는 아래 항목을 "추천안"으로 가정하고 작성했습니다. 다른 방향을 원하면 이 섹션과 관련 본문을 수정해주세요.

1. **획득 방식**: 동물별 게임을 클리어하면 **그 동물을 직접 확정 획득**합니다 (기존의 "카드 짝맞추기로 코인을 벌고 → 가챠로 랜덤 획득"이 아님).
2. **가챠/코인 폐지**: 위 1번에 따라 코인, 가챠 뽑기, 직접 구매(코인 소모) 기능은 **제거**합니다. 상점(`상점`) 탭 자체가 없어지고, 대신 "게임 목록" 탭이 그 자리를 대신합니다.
3. **진행 순서**: 12개 게임은 **자유 선택**입니다 (쥐→돼지 순서 강제 없음). 게임 목록 탭에서 아무 동물이나 골라 플레이할 수 있습니다.
4. **중복 획득**: 이미 클리어한 동물의 게임도 재도전 가능하며, 다시 클리어하면 보유 수량(`owned`)이 +1 됩니다 (기존 컬렉션 화면의 "x개" 표시를 그대로 재사용).
5. **난이도**: 동물별 게임은 스테이지 개념 없이 **고정 난이도 1종**으로 시작합니다 (기존처럼 스테이지가 오를수록 어려워지는 방식은 폐지). 필요하면 이후 별도 요청으로 난이도 단계를 추가할 수 있습니다.

## 1. 개요

기존에는 모든 동물이 동일한 카드 짝맞추기 퍼즐 하나만 공유했고, 퍼즐로 번 코인을 가챠에 써서 랜덤으로 동물을 얻는 구조였습니다. 이 스펙은 **12간지 동물마다 완전히 다른 미니게임**을 만들어, 해당 게임을 클리어해야 그 동물을 얻을 수 있도록 구조를 바꿉니다.

## 2. 전체 흐름

```
[게임] 탭
  ├─ 동물 12마리를 카드로 나열 (보유 수량 표시 포함)
  ├─ 동물 카드 클릭 → 그 동물 전용 미니게임 실행
  ├─ 게임 클리어 → 해당 동물 owned +1, 결과 메시지 표시
  └─ 게임 실패 → 실패 메시지, 재도전 버튼

[컬렉션] 탭
  └─ 기존과 동일 (12/12 모으면 승리 오버레이)
```

탭 구성: `게임` / `컬렉션` 2개로 축소 (`상점` 탭 제거).

## 3. 아키텍처 — 게임 모듈 인터페이스

12개 게임을 하나의 파일에 하드코딩하지 않고, **공통 인터페이스를 따르는 모듈**로 분리합니다. 각 게임은 아래 형태의 객체입니다:

```js
{
  id: 'rat',                     // ZODIAC id와 매칭
  instructions: '짝이 맞는 카드를...',  // 시작 전 안내 문구
  timeLimit: 45,                 // 초 단위 제한시간 (게임마다 다름)
  start(container, callbacks)    // 게임 시작, DOM은 container 내부에만 렌더링
  stop()                         // 타이머/이벤트 정리 (탭 전환, 재도전 시 호출)
}
```

- `callbacks.onWin()` — 게임 클리어 시 호출 → 공통 로직이 `owned[id] += 1`, 저장, 컬렉션/게임목록 갱신 처리.
- `callbacks.onFail(message)` — 실패 시 호출 → 공통 로직이 실패 메시지 표시, 재도전 버튼 노출.
- `start`/`stop`은 각 게임이 자신의 타이머(`setInterval` 등)와 DOM 이벤트 리스너를 스스로 관리하고 `stop()`에서 반드시 정리합니다 (다른 게임으로 전환할 때 메모리/타이머 누수 방지).

`script.js`에는 `GAME_REGISTRY = { rat: ratGame, ox: oxGame, ... }` 형태의 매핑만 두고, 공통 실행기(`launchGame(id)`)가 `container`를 비우고 해당 모듈의 `start()`를 호출하는 방식입니다.

## 4. 동물별 게임 명세

| 동물 | 컨셉 | 조작 | 클리어 조건 | 실패 조건 |
|---|---|---|---|---|
| 🐀 쥐 | 카드 짝맞추기 (기존 퍼즐 재사용) | 카드 클릭 | 4쌍 모두 매칭 | 제한시간(45초) 초과 |
| 🐂 소 | 밭 갈기 연타 게임 | 버튼 연타로 게이지 채우기 | 제한시간 내 게이지 100% | 제한시간 내 미달성 |
| 🐅 호랑이 | 반응속도 사냥 | 신호 뜨면 즉시 클릭 | 5라운드 평균 반응속도 기준 통과 | 신호 전에 클릭(오탐) 3회 |
| 🐇 토끼 | 타이밍 맞춰 멈추기 (좌우로 움직이는 바) | 정확한 순간에 클릭/스페이스 | 3회 연속 목표 구간 안에 정지 | 실패 횟수 초과 |
| 🐉 용 | 순서 기억 (사이먼 게임) | 색/방향 순서 보고 따라 클릭 | 5단계 순서 성공 | 순서 오류 1회 |
| 🐍 뱀 | 장애물 피하기 | 좌우 이동(방향키/버튼)으로 낙하물 피하기 | 제한시간 생존 | 장애물 3회 충돌 |
| 🐎 말 | 허들 넘기 타이밍 | 허들 앞에서 스페이스 클릭 | 5개 허들 통과 | 허들 충돌 2회 |
| 🐐 양 | 숫자 세기 | 지나가는 양 중 특정 색만 클릭 | 목표 개수 정확히 클릭 | 오답 클릭 3회 |
| 🐒 원숭이 | 두더지잡기 | 나타나는 원숭이 클릭 | 제한시간 내 목표 점수 달성 | 제한시간 내 미달성 |
| 🐓 닭 | 리듬 게임 | 박자에 맞춰 클릭 | 8박자 중 6박자 이상 정확히 | 박자 놓침 4회 |
| 🐕 개 | 다른 그림 찾기 | 격자에서 다른 이모지 1개 클릭 | 제한시간 내 정답 클릭 | 제한시간 초과 or 오답 3회 |
| 🐖 돼지 | 먹이 받아먹기 | 좌우 이동으로 떨어지는 먹이 받기 | 목표 개수 획득 | 목표 미달 or 다른 물체 3회 받음 |

각 게임의 정확한 수치(제한시간, 목표 점수 등)는 구현 단계에서 플레이 테스트로 조정합니다. 위 표는 "다른 종류의 조작/규칙"이라는 핵심만 고정하고 세부 밸런스는 구현 시 확정합니다.

## 5. 데이터 모델 변경

```js
function defaultState() {
  const owned = {};
  ZODIAC.forEach(a => { owned[a.id] = 0; });
  return { owned };   // coins, stage 필드 제거
}
```

- `coins`, `stage` 필드 제거.
- 기존 localStorage에 저장된 구버전 state(`coins`, `stage` 포함)를 불러올 경우, `owned`만 추출하고 나머지는 무시합니다 (별도 마이그레이션 UI 없이 조용히 무시).

## 6. UI 변경 (index.html)

- 상단 코인 표시(`coin-display`) 제거.
- 탭: `퍼즐` → `게임`, `상점` 탭 제거, `컬렉션` 유지.
- `게임` 탭 내부 구조:
  - 기본 화면: 12마리 동물 카드 그리드 (보유 수량 표시, 기존 `animal-grid` 스타일 재사용) → 클릭 시 해당 게임 화면으로 전환.
  - 게임 화면: 안내 문구, 제한시간/점수 표시 영역, 게임 전용 컨테이너(`#game-stage`), 뒤로가기 버튼.
- 승리 오버레이(12/12 컬렉션)는 기존 그대로 유지.

## 7. 파일 구성 제안

`script.js` 하나에 12개 게임 로직을 모두 넣으면 파일이 지나치게 커집니다. 아래처럼 분리합니다:

```
script.js          // 상태 관리, 탭 전환, 게임 목록 화면, launchGame() 공통 실행기
games/
  rat.js           // 기존 카드 짝맞추기 로직 이식
  ox.js
  tiger.js
  rabbit.js
  dragon.js
  snake.js
  horse.js
  goat.js
  monkey.js
  rooster.js
  dog.js
  pig.js
```

각 `games/*.js`는 `window.ZODIAC_GAMES = window.ZODIAC_GAMES || {}; window.ZODIAC_GAMES.rat = {...}` 형태로 자신을 등록합니다 (빌드 도구 없이 `<script>` 태그 순서로 로드하는 현재 프로젝트 구조에 맞춘 방식). `index.html`에 12개 `<script>` 태그를 `script.js`보다 먼저 추가합니다.

## 8. 구현 순서 제안

1. 게임 모듈 인터페이스 + `launchGame()` 공통 실행기 + 게임 목록 화면 뼈대 구현
2. 쥐 게임: 기존 카드 짝맞추기를 새 인터페이스 형태로 이식 (동작 검증용 기준점)
3. 나머지 11개 게임을 종류별로 순차 구현 (연타형 → 반응속도형 → 타이밍형 → 기억형 → 회피형 → 잡기형 순으로 유사한 게임끼리 묶어서 진행하면 재사용 가능한 유틸리티를 먼저 뽑아낼 수 있음)
4. 코인/가챠/상점 코드 제거, state 마이그레이션 처리
5. 전체 플레이 테스트: 12개 게임 각각 클리어/실패 케이스 확인, 컬렉션 12/12 승리 조건 확인

## 9. 검증 방법

- 각 게임: 클리어 시나리오 1회, 실패 시나리오 1회를 브라우저에서 직접 플레이하여 확인.
- 게임 전환 시 이전 게임의 타이머/이벤트 리스너가 남아있지 않은지 확인 (예: 소 게임 도중 뒤로가기 후 다른 게임 진입해도 이전 연타 카운트가 영향 주지 않아야 함).
- localStorage에 구버전 state(coins/stage 포함)를 넣어두고 로드했을 때 에러 없이 `owned`만 반영되는지 확인.
- 12마리 전부 획득 시 승리 오버레이가 정상 표시되는지 확인.
